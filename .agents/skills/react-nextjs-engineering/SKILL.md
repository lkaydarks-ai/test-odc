# React and Next.js engineering

1. Detect React/Next.js version, router (App Router or Pages Router), TypeScript, styling, data fetching and test setup.
2. Follow existing conventions and current framework APIs; verify uncertain or version-sensitive APIs against installed docs/package types.
3. Keep server/client boundaries intentional. Prefer Server Components when appropriate; use client components only for interactivity/browser APIs.
4. Use semantic HTML, accessible labels, keyboard navigation, focus management and sufficient contrast.
5. Design responsive layouts for narrow mobile, tablet and desktop; avoid overflow and fixed-width assumptions.
6. Include loading, error, empty, disabled and optimistic states where appropriate.
7. Keep components focused; extract shared UI only when reuse or clarity warrants it.
8. Avoid unnecessary effects, duplicated state, prop drilling where existing context/store patterns solve it, and premature abstractions.
9. Handle forms with schema validation and clear field-level errors. Never trust client-side validation alone.
10. Optimize images, fonts, bundle size, rendering and caching based on measured needs.
11. Add component/integration/E2E tests for meaningful user flows.
12. Check metadata, SEO, route protection and server-side authorization where relevant.
13. Run lint, typecheck, tests and production build; report exact outcomes.
